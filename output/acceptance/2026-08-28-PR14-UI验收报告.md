## 逐项详情

### 1. 手动录入原始需求

- **复现步骤**：点击顶部「原始需求识别」→ 输入原始反馈文本（或点击预设「C706 踏频低电量提示」）。
- **实际表现**：实时显示字数统计与上限校验，暂存与预设填充顺畅。
- **预期表现**：支持输入 1~20000 字原始反馈，不丢失文本。
- **是否需要修改代码**：否

### 2. AI 识别改写功能需求与缺口分析

- **复现步骤**：输入原文后点击「保存原文并开始 AI 识别」→ 观察右侧识别结果卡片。
- **实际表现**：工作包先落盘存入 `requests/RAW-xxx/source.md`，展示需求分类（如「码表 / 传感器」）、结构化改写的功能需求、人群归位（L1~L3）、关键待确认缺口及知识库关联依据（如 `BENCHMARK.md`）。
- **预期表现**：正确改写为功能需求，标记待澄清缺口。
- **是否需要修改代码**：否

### 3. 将需求登记到需求池

- **复现步骤**：在识别结果卡片底部点击「确认登记为正式需求」。
- **实际表现**：状态由 `pending_confirmation` 迁入 `pending_launch`，创建正式工作包 `REQ-xxx` 与 `agent-task.md`，自动跳转进入任务卡详情页并触发前置检查。
- **预期表现**：PM 权威动作才能登记为正式需求并生成工作包。
- **是否需要修改代码**：否

### 4. 执行 Preflight 前置环境检查

- **复现步骤**：在工作包详情页观察「Claude Code 启动前环境检查」卡片；切换模拟场景（CLI 未安装 / 未认证 / 正常）。
- **实际表现**：8 项检查实时执行（项目目录、写权限、CLI 安装、版本号、认证、规则入口、任务卡可读性、output 写权限）。环境不就绪时禁用启动按钮，展示结构化修复建议与一键复制命令。
- **预期表现**：检查项清晰，提供可行动指引。
- **是否需要修改代码**：否

### 5. 启动 Claude Code 建立会话

- **复现步骤**：检查全部通过后点击「打开外部终端并启动 Agent」。
- **实际表现**：桥接层执行受控种子初始化（写入 `envelope.session_id`），拉起外部终端运行 `claude --resume <id>`；Web 展示绿色脉冲呼吸灯、Session ID 与启动时间，状态迁入 `processing`。
- **预期表现**：打开正确项目目录并启动会话。
- **是否需要修改代码**：否

### 6. 等待 Agent 返回澄清问题
