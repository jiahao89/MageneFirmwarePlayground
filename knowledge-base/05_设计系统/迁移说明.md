# 迁移说明

本次整理不删除历史文件，避免丢失已有依据；但新增或修改设计规则只能更新本目录的正式规范。

| 正式规范 | 主要历史来源 | 当前维护方式 |
| --- | --- | --- |
| `01_顽鹿App/设计规范.md` | `design system/01_核心规范.md`、`02_APP组件规范.md` | 顽鹿 App 的唯一正式规范 |
| `02_迈金C706/设计规范.md` | `design system/01_核心规范.md`、`03_C706码表规范.md`、`屏幕尺寸.md` | C706 的唯一正式规范 |
| `03_GEOID/设计规范.md` | `GEOID_Design/design-spec.md`、`vi-spec.md`、`style-guide.md` | GEOID 的唯一正式规范 |
| `04_跨端流程规范.md` | `design system/04_状态与流程规范.md` | App 与码表联动的唯一正式规范 |
| `05_工具适配/` | 原 Figma、Stitch、Pen.dev 文件 | 工具执行方式的唯一正式规范 |

## 维护规则

1. 新 Token、组件、状态或页面规则，先写入对应的三套正式规范之一；跨端规则写入 `04_跨端流程规范.md`。
2. 影响“读取哪些文件”的变化，只改 `design-manifest.json`；路由脚本不手写规则矩阵。
3. 历史目录只保留来源和迁移提示。需要保留新旧差异时，在本文件追加说明，不在两边复制同一条规则。
4. 新增第四套产品设计语言时，新建一份完整的 `设计规范.md`，再在 `design-manifest.json` 增加目标；不要在现有三套规范中拼接例外条目。
