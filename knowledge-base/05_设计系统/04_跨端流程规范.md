# 跨端流程规范

## 1. 适用范围

本文件用于顽鹿 App 与迈金 C706、或顽鹿 App 与 GEOID 码表的连接、同步、传感器、OTA、恢复等任务。它只规定用户可见的状态和页面关系，不替代 PRD 的业务状态机或固件实现方案。

## 2. 用户可见状态

| 状态 | 用户看到什么 | 页面需要表达什么 |
| --- | --- | --- |
| 未开始 | 说明与发起入口 | 用户将要做什么 |
| 准备中 | 阶段文案或短提示 | 正在准备什么；避免重复发起 |
| 连接中 | 设备/传感器图标和连接中 | 不把连接中当成已连接 |
| 已连接/可用 | 图标、文案或可用内容 | 当前可执行什么 |
| 同步中 | 同步方向、任务或进度 | 避免冲突修改 |
| 成功 | 结果与下一步 | 不只显示短暂 Toast |
| 失败 | 短原因与下一步 | 可重试、需检查条件或不可继续 |
| 禁止/不兼容 | 阻止原因和解决建议 | 用户如何解除阻止 |
| 超时/断开 | 中断提示 | 是否可重试、应检查什么 |
| 恢复中 | 恢复阶段与限制 | 按 PRD 限制退出和重复操作 |

状态至少由颜色、图标、文字、位置、进度、形状中的两种表达。错误主文案面向用户行动，例如“请重新连接码表”，不默认展示内部错误码。

## 3. 流程图与连线图

- 流程图只连接用户实际看见或操作的 App / 码表页面；不复用整张设计 Frame 作为流程节点。
- 正常路径用实线；仅已确认的异常路径用虚线。
- 异常节点注明触发条件和用户下一步；自动恢复、自动切换和回滚未经确认时标为“待确认”。
- App 与码表分别放在独立泳道，连线表示用户动作或系统反馈，不把两端页面拼成同一屏。

## 4. OTA 与恢复

### 4.1 用户可见的整体 OTA

```text
待升级 → 准备 → 下载 → 校验 → 安装 → 重启/启动确认 → 完成
```

- App 显示整体进度、阶段、常见阻止原因与整体结果。
- 码表显示必要的确认、短状态、完成或恢复画面。
- 不向用户拆分主芯片、从芯片、差分包、分区等内部实现。
- 未确认的差分失败后自动切全量包只记录为待确认，不画成已实现路径。

### 4.2 已确认的回归路径

| 场景 | App | 码表 |
| --- | --- | --- |
| Recovery 成功 | 回到码表设置，等待设备重连并刷新版本 | 自动重启后回首页；无继续按钮 |
| 从节点更新失败 | 显示整体“升级失败”，按产品能力重试/退出 | 提示“升级失败”，可重新下载或重试；不进入 Recovery |
| Recovery 失败 | 使用已确认的失败反馈，不增加长解释 | 仅使用失败图片或短提示 |

正常 OTA 的 App 和码表均不提供中途返回；用户只能按已确认的系统方式结束 App 或关闭设备。原型不新增“取消升级”或返回路径。

## 5. 跨端交付检查

- [ ] 两端页面分别遵循各自设计系统，没有互相复制布局。
- [ ] 每条连线是用户动作或系统反馈，异常路径均已确认或标注待确认。
- [ ] 覆盖适用的准备、进行中、成功、失败、阻止和恢复状态。
- [ ] OTA 以一次整体任务表达，未泄露内部实现细节。
- [ ] 成功后的 App 与码表回归页面正确。
