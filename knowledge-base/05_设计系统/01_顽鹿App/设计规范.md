# 顽鹿 App 设计规范

## 1. 设计语言

顽鹿 App 是骑行设备的手机控制端：深色、克制、运动感强，以清晰的设备状态和任务推进为核心。它可以承载说明、设备信息、下载和设置，但不把固件实现细节展示给用户。

- 默认与当前正式主题：**Dark**。Light 主题尚无已确认 Token，不得由 Agent 自行反推或生成第二套主题。
- 视觉结构：深色页面底 + 层级清楚的深色容器 + 荧光黄绿色的主行动。
- 主色硬约束：所有 Primary Button、选中态、主焦点、主进度和品牌强调必须使用 `app/color/brand/primary = #C6FF00`；不得用橙色、红色或蓝色替代主色。
- 参考稿只用于学习布局和信息层级。参考稿中的历史色值与正式 Token 冲突时，以本文件为准。
- 信息原则：一个页面一个主要任务；页面内通常只有一个 Primary Action。
- 内容可纵向滚动；任务流中不显示一级底部导航。

## 2. Token

### 2.1 颜色

| 语义 Token | 值 | 用途 |
| --- | --- | --- |
| `app/color/brand/primary` | `#C6FF00` | 唯一主操作、品牌强调 |
| `app/color/action/secondary` | `#00B0FF` | 链接、次级可操作强调 |
| `app/color/bg/page` | `#0A1011` | 页面底色 |
| `app/color/bg/card` | `#151E1E` | 卡片、任务容器 |
| `app/color/bg/input` | `#2A3131` | 搜索、输入、弱容器 |
| `app/color/text/primary` | `#FFFFFF` | 标题、主要内容 |
| `app/color/text/secondary` | `#FFFFFF99` | 辅助说明 |
| `app/color/text/tertiary` | `#FFFFFF66` | 弱提示、占位 |
| `app/color/border/default` | `#FFFFFF33` | 容器边界 |
| `app/color/border/divider` | `#FFFFFF26` | 列表分割 |
| `app/color/status/success` | `#2CC683` | 已连接、成功、完成 |
| `app/color/status/warning` | `#FFA423` | 低电量、风险、待注意 |
| `app/color/status/error` | `#F14867` | 失败、阻止、不可继续 |

主色使用检查：页面中至少应能找到一个主色承担“当前选中、主操作或品牌强调”中的一种；如果页面没有主操作，也不能把状态色误当成品牌主色。

状态弱背景使用对应的 `dark` 色阶：成功 `#2B6A40`、警告 `#845A1A`、失败 `#8E3F4E`。状态色必须与图标或短文案组合使用。

### 2.2 间距、圆角与图标

| Token | 值 | 规则 |
| --- | --- | --- |
| `space/2xs` / `xs` / `sm` | 4 / 8 / 12px | 图标、行内和紧凑组件 |
| `space/md` / `lg` / `xl` | 16 / 24 / 32px | 卡片内边距、模块间距、页面节奏 |
| `radius/sm` / `md` / `lg` / `xl` | 8 / 16 / 24 / 32px | 小控件、按钮/卡片、大卡片、底部弹层 |
| `radius/full` | 100px | 胶囊标签、圆形图标按钮 |

图标使用同一套线性或填充体系；同一层级不得混用线宽和风格。可见图标小于触摸区域时，仍保持完整点击热区；所有可点击区域至少 `44 × 44pt`。

### 2.3 字体与层级

正文使用 `SF Pro Text`；大数据可使用 `Saira`。使用以下层级，不用自动行高：

| Token | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `font/heading/h1` | 40 / 48 | 高层级页面标题 |
| `font/heading/h2` | 36 / 44 | 页面标题 |
| `font/heading/h3` | 32 / 40 | 模块标题 |
| `font/heading/h4` | 28 / 36 | 卡片标题 |
| `font/body/md` | 28 / 40 | 多行说明 |
| `font/body/sm` | 24 / 32 | 简短说明 |
| `font/label/md` | 28 / 32 | 单行标签、按钮 |
| `font/caption/sm` | 22 / 24 | 时间、弱提示 |
| `font/number/lg` | 56 / 64 | 核心运动数据 |

## 3. 导航与页面骨架

### 3.1 顶部导航与标题

- 顶部导航承担返回目的地和页面级操作；标题说明当前页面。
- 简单页面可把标题放在顶部导航内，避免重复标题。
- 设备设置、OTA、下载、恢复和确认属于任务流：使用顶部返回或退出能力，但是否允许退出以 PRD 为准。

### 3.2 底部导航

- 仅用于 App 一级目的地，数量不超过 5 个。
- 当前项必须有文字和视觉选中态；图标不能单独承担导航含义。
- 进入设备设置、OTA、下载、恢复、确认等任务页后不显示底部导航，避免意外中断任务。

### 3.3 页面模板

```text
Top Navigation
Page Title（可选）
Device Summary / Status Card（按需）
Main Content
Primary Action（按需，通常一个）
```

任务页：`Top Navigation → Task Title → Progress / Status → 简短说明 → 已确认操作`。

## 4. 组件库

| 组件 | 必备状态与规则 |
| --- | --- |
| Button | `Default / Pressed / Disabled / Loading / Success / Error`；Primary 每页通常一个；Danger 必须说明后果并二次确认 |
| Input / Search | 标签、输入、占位、错误、禁用、清除或返回策略；无结果使用 Empty State |
| List Item | 标题、可选辅助信息、右侧状态/箭头/控件；整行可点击；支持同步中、异常、不兼容 |
| Switch | 只用于即时生效二态；会下发、重启或不可逆的操作改用确认或任务流 |
| Device Summary | 型号、连接、电量、固件版本、同步状态；“显示设备信息”不等于“已连接” |
| Status Card | 图标、短标题、原因或进度、可处理的下一步 |
| Dialog / Bottom Sheet | Dialog 用于确认或阻止；Bottom Sheet 用于选择和补充操作；危险操作说明影响 |
| OTA Progress | 面向用户显示整体任务：准备、下载、校验、安装、重启确认、完成/恢复；不展示主从芯片、分区或差分包 |
| Empty / Loading / Error | 分别设计：空状态说明为什么为空；加载说明正在做什么；失败说明是否可重试与下一步 |

## 5. 交互、状态与可用性

- 点击后在 `80–150ms` 内有按下反馈；微交互通常 `150–300ms`，不改变布局边界。
- Disabled 必须同时降低视觉权重并说明前置条件；不可点击区域不保留点击行为。
- 文字对比、状态边界、分割线在深色主题下保持可辨识；正文与背景保持足够对比。
- 状态以颜色、图标、文字、位置、形状或进度中的至少两种表达。
- 固定顶部或底部元素要避开系统安全区；滚动内容不能被固定元素遮挡。

## 6. App 自检

- [ ] 使用了顽鹿 App Token 与组件，而不是码表或 GEOID 的视觉语言。
- [ ] Primary、选中态、主焦点和品牌强调使用 `#C6FF00`；没有用橙色替代顽鹿主色。
- [ ] 参考 Figma 页面只作为布局参考，未覆盖正式 Token。
- [ ] 页面主任务和唯一主操作清楚。
- [ ] 导航层级正确：一级页可显示底部导航；任务页不显示。
- [ ] 覆盖适用的 Default、Loading、Empty、Disabled、Success、Error。
- [ ] OTA 等任务只表达用户可理解的整体流程。
- [ ] 没有新增未确认的硬件能力、返回机制或自动恢复逻辑。
