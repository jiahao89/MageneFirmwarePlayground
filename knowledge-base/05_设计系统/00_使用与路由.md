# 使用与路由

## 1. 先选系统，再画页面

每项设计先确认以下信息：

```text
目标系统：顽鹿 App / 迈金 C706 / GEOID 极遨
任务类型：单页或组件 / 跨端流程 / 设计系统维护
工具：Figma / Stitch / Pen.dev / 无
GEOID 专属：机型与尺寸、Dark / Light / Both
```

信息会改变页面尺寸、视觉语言、状态或可用操作时，先标记待确认；其中 GEOID 的机型和模式缺失时，不生成最终原型。

## 2. 规则归属

| 规则 | 唯一依据 |
| --- | --- |
| 页面范围、业务状态、允许操作 | 当前已确认 PRD |
| 顽鹿 App 的颜色、组件、导航和页面结构 | `01_顽鹿App/设计规范.md` |
| C706 的尺寸、状态栏、数据页面与触摸边界 | `02_迈金C706/设计规范.md` |
| GEOID 的双模式 Token、品牌图形、字体与组件 | `03_GEOID/设计规范.md` |
| App 与码表共同任务的状态和回归路径 | `04_跨端流程规范.md` |
| Figma、Stitch、Pen.dev 的画布与组件操作 | `05_工具适配/` 下对应文件 |

同一页面只使用一个目标系统的视觉 Token 和组件语言。跨端流程可以同时引用多个系统，但每一端的页面必须仍使用自己的规范；不得把 App 卡片、C706 数据格和 GEOID 装饰互相套用。


## 4. 共同质量底线

- 页面只服务一个主要任务或一个核心骑行信息；主操作通常不超过一个。
- 连接、加载、禁用、成功、失败和风险不能只靠颜色；至少结合文字、图标、位置、形状或进度中的一种。
- 未由需求确认的实体按键、硬件能力、自动恢复、通信行为和导航跳转不自行补充。
- 正式图标使用统一的矢量图标语言；Logo、字体或插画未交付时使用明确占位并标注待替换，不用 emoji 或字符冒充正式图标。
- 组件和页面必须采用语义化名称；不使用工具内部编号作为业务名称。
- 参考 Figma 只提供布局和交互线索；如果参考稿与目标设计系统 Token 冲突，正式设计系统优先，Agent 必须在上下文卡中记录该裁决。

### 顽鹿 App 颜色硬校验

生成顽鹿 App 前必须先确认：`page = #0A1011`、`card = #151E1E`、`primary = #C6FF00`。Primary、选中态、主进度和品牌强调不得出现橙色替代主色；橙色只能在 PRD 明确的业务状态或数据编码中使用，不能作为 App 主按钮或主品牌色。

## 5. 完成条件

交付前满足：

- 已读取路由返回的全部文件；
- 每个页面的目标系统、尺寸、状态和可执行操作明确；
- 已覆盖适用的 Default、Loading、Empty、Disabled、Success、Error 状态；
- 已按目标系统的交付检查复核；
- 所有无法验证或尚未确认的内容已标注，不把推测当成规则。
