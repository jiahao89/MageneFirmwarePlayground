# 原型验收清单

> 原型验收同时检查视觉结构和产品行为。页面“看起来完整”不等于需求已经覆盖。

## 1. 需求覆盖

- [ ] 每条纳入本期的需求都有对应页面、状态、操作或明确“不需要页面”。
- [ ] 页面、状态、操作和验收项可以通过 ID 互相追踪。
- [ ] 原型没有引入正式 PRD 未确认的新功能。
- [ ] 不在范围内的功能没有被 AI 自动补入。

## 2. 流程与状态

- [ ] 入口、主流程、成功结果和返回路径完整。
- [ ] 加载/连接中、空状态、失败、超时、断连等状态按需覆盖。
- [ ] 每个按钮或手势都有明确结果。
- [ ] 不可操作状态有原因或下一步。
- [ ] App 与 C706 的状态表达一致但不强行使用相同页面。

## 3. 固件 PM 专项

- [ ] 码表离线时的行为已明确或标记待确认。
- [ ] 断连、关机、断电、重启是否影响任务已明确或标记待确认。
- [ ] 版本、机型、国内/海外差异已体现。
- [ ] 传感器、车灯、雷达、OTA 等涉及的状态没有只用一个“连接/失败”概括。
- [ ] 没有擅自假设实体按键、协议、硬件能力或自动恢复逻辑。

## 4. 设计系统

- [ ] 目标端明确，使用了对应端的设计规范。
- [ ] C706 页面为 320 × 480 px，无滚动、裁切或底部伪操作栏。
- [ ] 组件、颜色、间距和状态语义符合当前设计系统。
- [ ] 关键状态不只依赖颜色表达。
- [ ] 文案长度、多语言和数值单位没有明显溢出风险。
