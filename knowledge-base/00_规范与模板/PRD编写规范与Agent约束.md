# 迈金室外固件 PRD 编写规范与 Agent 约束

> 本文件是 PRD 写作指南，不是实际 PRD 模板。实际写作请使用轻量功能迭代模板或复杂/新功能模板。

## 1. 模板选择

根据需求范围选择模板，不要为了“看起来完整”给小改动套用复杂模板。

| 模板 | 适用场景 | 典型例子 | 交付重点 |
|---|---|---|---|
| [轻量功能迭代模板](PRD模板-轻量功能迭代.md) | 现有功能迭代、小功能、单点规则调整、页面文案/交互调整 | 增加开关、修改提示、调整回连规则、增加一个数据项 | 变更边界、主流程、功能说明、验收 |
| [复杂/新功能模板](PRD模板-复杂新功能.md) | 新设备、新协议、跨码表/App/后台的完整能力、复杂状态机、完整 OTA 流程 | 添加 Radar/LEV/FE-C 设备、全新训练功能、OTA 升级体系 | 系统关系、主流程、功能说明、按需补充技术约束 |

## 2. 统一填写规则

### 2.1 基本信息

每份 PRD 至少填写：需求名称、负责人、需求来源、适用产品/版本、文档状态和更新时间。

### 2.2 区分事实、判断与待确认

- **事实**：已有文档、设备实测、研发确认或官方协议明确说明的内容。
- **判断**：PM 基于事实做出的方案选择，必要时说明依据。
- **待确认**：会影响范围、流程、交互或实现的未决问题。

不得把待确认内容写成确定结论。

### 2.3 一条需求尽量只表达一个可验收行为

复杂需求可使用 `REQ-001`、`AC-001` 等 ID 追踪；轻量需求不强制编号。每条需求尽量只写清“触发条件—系统行为—结果”。

### 2.4 三层架构按需填写

涉及对应内容时，再补充：

1. **硬件/物理层**：屏幕、按键、声音、灯、传感器、功耗或无线资源。
2. **固件/协议层**：ANT+ Device Profile、BLE GATT、状态、配置、**FIT**、断电保护或 OTA。
3. **App 业务层**：OnelapFit 的配置、设备管理、同步、提示或升级。

### 2.5 图按需选择

- 功能范围：优先思维导图，无法清晰表达时使用表格。
- 主流程：使用流程图。
- 多端协作：使用时序图。
- 状态较多：使用状态图。

不要求所有文档都使用全部图形。

### 2.6 页面描述边界

PRD 只写页面入口、跳转、操作、状态、反馈和文案。不要用 Markdown 绘制线框原型；视觉设计由 PM/设计稿补充。

### 2.7 技术细节边界

指标、接口、字段、埋点、详细协议和测试矩阵不作为固定章节，仅在影响产品行为、兼容性或验收时补充。

## 3. 评审检查

- [ ] 能用一段话说明问题、目标和本期范围。
- [ ] 已说明用户如何使用以及系统如何反馈。
- [ ] 主流程、异常流程和关键边界已区分。
- [ ] 适用机型和版本已明确，或标记待确认。
- [ ] 不确定内容已进入待确认项，没有隐含猜测。
- [ ] 需要时已补充设备、协议、状态、兼容性或验收要求。

## 4. 推荐工作方式

1. 先写背景、目标、方案、范围、流程和功能说明。
2. 将初版 PRD 交给 Agent 生成主要原型。
3. 根据原型和评审结果，补充技术约束、异常流程和验收内容。
4. 项目专属结论写入项目 PRD，不写入本规范。
