# 码表产品线 — PRD 写作风格

> 模板结构以 `knowledge-base/00_规范与模板/` 的现行模板为准（轻量/复杂两套，0-9 章节 + 三层架构）。
> 本文件补充**跨模板通用的写作习惯**，融合自 prd-generator 的码表风格约定与 workspace 的现行规范。

## 一、品牌与平台（必须标注）

- 公司：迈金科技（Magene）
- 国内 App：**顽鹿运动** / 海外 App：**OnelapFit**
- 凡国内/海外行为有差异的，**必须明确标注**（如"海外版码表首次开机需激活，国内版无此步骤"）

## 二、三层架构按需填写

每个功能按相关性填写「硬件/物理层 → 固件/协议层 → App 业务层」，不涉及的层级写"不涉及"或直接省略，**不得为填满而编造**。协议要明确到 ANT+ Device Profile / BLE GATT / 迈金私有服务；涉及 FIT、断电保护、OTA 时再补充对应规则。

## 三、事实 / 判断 / 待确认 三分

- **事实**：已有文档、实测、研发/官方协议确认的内容
- **判断**：PM 基于事实做的方案选择，必要时说明依据
- **待确认**：会影响范围/流程/交互/实现，且尚未定论
- 不确定一律标"待定"/"待确认"/"pv版本待定"；有歧义列"方案1/方案2/方案3"，**绝不假装知道**

## 四、交互细节精确到字

- **结论先行**："结论先行：XX"
- **Toast 文案精确到字**："配对失败，请重试（未搜索到设备）"
- **超时精确标注**："超时时间：十秒"
- **开关带默认值**："出厂默认XX"
- **异常内联**，不单独成章
- 负责人用 **@人名** 标注（如 @刘媛媛 / @毕梓浩）

## 五、弹窗体系优先级队列（码表特有）

同时触发多个弹窗时，按下表优先级排序：

| 排序 | 性质 | 场景示例 |
|------|------|---------|
| 🔴 最高 | 安全预警 | 关机提醒、断点续骑询问 |
| 🟠 | 核心指令 | 手动关机、结束骑行确认 |
| 🟡 | 骑行辅助 | 爬坡提醒、赛段提醒 |
| 🟡 | 通知提醒 | 智联助手、来电 |
| 🟢 | 导航引导 | 转向、偏航 |
| 🟢 | 事务操作 | 删除确认、数据项选择 |
| ⚪ | 操作指引 | 新手引导 |
| ⚪ 最低 | 状态反馈 | 收藏成功、上传成功 |

## 六、图与页面边界

- 图按需选择：功能范围用思维导图、主流程用流程图、多端协作用时序图、状态多用状态图——**不要求全画**
- 页面只写入口/跳转/操作/状态/反馈/文案，**不用 Markdown 画线框原型**，视觉交给设计稿
- 技术细节（指标/接口/字段/埋点/详细协议）不作固定章节，仅在影响产品行为/兼容性/验收时补充

## 七、引用与基线

- 频繁**沿用历史基线**："沿用 XX 方案"、"同步自文档: https://..."
- 跨文档引用："详见 5.9"、"见软件 prd xxx"
- 项目专属结论写入项目 PRD，不写入全局规范
