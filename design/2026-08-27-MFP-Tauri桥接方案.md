# MFP Tauri 原生桥接方案（Issue #6 后端子任务）

> 状态：macOS 已实现并通过测试；Rust 层编译验证进行中（见 PR）。
> 适用范围：Tauri 桌面壳 ↔ 本地桥接层。浏览器预览（`npm run dev` 直开）仍走
> `BrowserMockBridge`，**不代表桌面 App 可用**。

## 架构：Rust 薄代理 + Node 桥接服务

```
┌────────────────────────┐
│ React Web UI（src/web） │   invoke('save_raw_input', {req}) …
└──────────┬─────────────┘
           │ Tauri IPC（命令名 = 契约操作名）
┌──────────▼─────────────────────────────┐
│ Rust 命令层（src-tauri/src/commands.rs）│   薄代理：
│  - 定位 node / bridge-server.cjs        │   ① 定位运行时与脚本
│  - 参数数组拉起子进程（cwd = MFP 根）    │   ② 透传参数与结果
│  - 行分隔 JSON-RPC 转发 + id 关联       │   ③ 透传错误消息
└──────────┬─────────────────────────────┘
           │ stdin/stdout（行分隔 JSON）；stderr = 诊断
┌──────────▼─────────────────────────────┐
│ Node 桥接服务（dist-bridge/bridge-server.cjs）│
│  → LocalBridge / ClaudeCliAdapter /    │   ★ 契约、状态机、持久化、
│    terminal-launcher（全部 TS 实现）     │     CLI 适配的唯一实现
└──────────┬─────────────────────────────┘
           │ 参数数组（shell:false）
┌──────────▼──────────────┐
│ 外部 Terminal + claude CLI │  macOS Terminal（osascript）/ wt / PowerShell
└─────────────────────────┘
```

### 为什么不做「纯 Rust 实现」

需求状态机、工作包校验、会话降级、终端启动已经在 TypeScript 桥接层实现并测试
（Issue #2/#3，89 用例）。若 Rust 再实现一遍，必然形成两套互相矛盾的状态机。
因此：**Rust 命令层零业务逻辑**——

- 入参仅 `SaveRawInputRequest` 等少量结构（与 invoke 参数同形），其余为标量；
- 返回值一律 `serde_json::Value` 原样透传，Rust 不镜像 `WorkPackage` 类型；
- 错误取桥接层 `payload.message`（可行动中文文案）作为 invoke 的 `Err(String)`；
- 契约唯一事实来源仍是 `src/bridge/types.ts` + `state-machine.ts`。

## RPC 协议

`stdin` / `stdout` 每行一个 JSON（诊断日志只走 `stderr`）：

```jsonc
→ {"id":1,"method":"saveRawInput","params":{"req":{"text":"…","sourceDescription":"…"}}}
← {"id":1,"ok":true,"result":{ /* WorkPackage */ }}
← {"id":1,"ok":false,"error":{"code":"INVALID_TRANSITION","category":"state","message":"非法状态迁移：…"}}
```

- `method` = `MfpBridge` 操作名（`saveRawInput` … `archive`，另加 `ping`）；
- `params` 形状 = 前端 invoke 参数，Rust 零转换透传；
- 响应按 `id` 关联（Rust 客户端容忍噪声行）。

## 运行时定位与配置（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `MFP_ROOT` | 当前工作目录 | **MFP 项目根目录**；桥接服务进程与终端会话的 cwd 都固定为它，`PathGuard` 约束一切路径 |
| `MFP_NODE` | PATH 中的 `node` | Node 可执行文件 |
| `MFP_BRIDGE_SERVER` | 见候选列表 | `bridge-server.cjs` 路径；候选：`$CWD/dist-bridge/`、`$CWD/app/dist-bridge/`、可执行文件目录 |
| `MFP_ADAPTER` | `claude` | `claude`（真实 CLI）或 `fake`（确定性测试适配器） |
| `MFP_TERMINAL_APP` | `Terminal` | macOS 终端应用名 |

## 本机运行

```bash
cd app
npm install
npm run build:bridge                    # 产出 dist-bridge/bridge-server.cjs（+fake-cli 夹具）
MFP_ROOT=/path/to/MageneFirmwarePlayground npm run tauri dev
```

`tauri dev` 的 `beforeDevCommand` 已自动先跑 `build:bridge`；`npm run build`
（打包前）也已包含它。

## 跨平台边界

- **macOS**（本机已实现/测试）：终端经 `osascript` 驱动 Terminal；真实 `claude 2.1.229`
  的 flag 与会话文件布局已实测。
- **Windows**（代码已实现，待真机验证）：`wt.exe` 优先 → `powershell.exe` 回退，
  逻辑在 TS `terminal-launcher.ts`（纯函数计划有测试）；Rust 拉起 node 子进程为
  平台无关的 `Command` 参数数组。**Windows 真机验证属 Issue #6 联调验收项**。

## 安全不变量（延续 #7/#3，全部有测试）

1. **API key 不落盘、不进日志**：认证归 Claude Code；桥接服务只转述认证错误；
   诊断走 `stderr` 且只输出可行动消息；工作包文件无凭据字段（测试锁定）。
2. **用户文本不进命令行**：Rust → node 为参数数组（受控值）；识别走 `stdin`；
   终端会话走启动文件；测试锁定启动计划不含用户文本。
3. **路径约束**：`MFP_ROOT` 经 `PathGuard` 固定，`..`/符号链接逃逸被拒绝。

## 错误传播

`BridgeError payload` → RPC `error` 对象 → Rust 取 `message` → invoke 拒绝 →
前端 `alert(message)`。常见码：`CLI_NOT_FOUND`（未装 claude）/ `CLI_AUTH_FAILED`
（登录失效）/ `INVALID_TRANSITION`（状态机）/ `CONCURRENT_RUN` / `SESSION_NOT_FOUND`
（resume 降级）/ `TERMINAL_LAUNCH_FAILED`。
