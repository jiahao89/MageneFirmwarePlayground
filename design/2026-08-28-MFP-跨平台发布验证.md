# MFP 跨平台发布验证（Issue #6 Windows 清单 + 打包）

> 状态：macOS 侧已真实验证（含安装包）；Windows 侧可本地确定性验证的部分已全部测试化，
> 真机部分由 `app/scripts/verify-windows.ps1` 一键执行。本文档为执行 runbook。

## 一、本轮交付

### 打包资源链路（跨平台发布核心）

- `tauri.conf.json` → `bundle.resources: ["../dist-bridge/*"]`：桥接服务打进安装包
  （macOS 落 `.app/Contents/Resources/dist-bridge/`，Windows 落安装目录）。
- Rust `server_script_candidates` 新增 **resource_dir 候选**；`lib.rs` setup 时经
  `app.path().resource_dir()` 注入。安装包启动后无需任何环境变量即可定位桥接服务。
- `find_in_path` 分隔符参数化（`find_in_path_with_sep`），macOS 上可测试 Windows 的
  `;` 分隔解析。
- TS 侧 `resolveBinaryPath(cliPath, pathEnv, platform)` 抽为纯函数（win32：
  `;` 分隔 + `node.exe`/`node.cmd` 候选），可跨平台单测。

### 新增测试（`test/cross-platform.test.ts` 8 例 + Rust 2 例）

| 覆盖 | 说明 |
|---|---|
| wt / PowerShell 启动计划 × Windows 路径 | 中文/空格路径原样单参数传递；`Get-Content -Raw '<路径>'` 引用正确 |
| PowerShell 转义 | 单引号加倍（`it's` → `it''s`）；反斜杠不转义 |
| 长文本不进命令行 | 两套计划均不含启动指令正文 |
| resume 模式 | Windows 计划用 `--resume`，不用 `--session-id` |
| PATH 解析 | win32 `;` 分隔 + `.cmd` 候选命中；darwin 语义不误命中 |
| 会话目录 sanitization | 盘符路径 `C:\Users\x\MFP` → `C--Users-x-MFP`（规则外推，真机核对见下） |
| 打包布局候选 | macOS Resources 与 Windows 安装目录两种 resource_dir |

### Windows 真机一键验证（`app/scripts/verify-windows.ps1`）

覆盖 Issue #6 Windows 清单第 1/2/5/6/9 项（node 定位 / 脚本定位 / claude CLI /
sanitization 核对 / 终端可用性 + 启动计划展示），RPC 冒烟用 `--adapter fake`
不消耗模型调用。第 3/4 项（真实启动会话）用桌面 App 走完整流程。

## 二、Windows 真机验证步骤

```powershell
# 0. 前置：安装 Node.js ≥ 20 与 Claude Code（claude 登录）
git clone <repo>; cd MageneFirmwarePlayground\app
npm install
npm run build:bridge

# 1. 一键验证（第 1/2/5/6/9 项）
powershell -ExecutionPolicy Bypass -File scripts\verify-windows.ps1 -Root ..

# 2. 桌面 App 完整流程（第 3/4 项：真实启动/恢复会话）
npm run tauri dev   # 或安装打包产物
#    UI：录入 → 识别 → 登记 → 启动（观察 wt/PowerShell 打开、claude 启动、
#        cwd=MFP 根目录）→ 回答 → 关终端 → 恢复会话（应真正 resume）

# 3.（可选）验证终端窗口打开（不调用模型）
powershell -ExecutionPolicy Bypass -File scripts\verify-windows.ps1 -Root .. -OpenTerminal
```

**通过标准**：脚本输出 `N/N 全部通过`；App 完整流程中 Terminal/PowerShell 正确打开、
`claude --resume <id>` 启动、工作目录为 MFP 根目录。

## 三、打包与安装包验证（macOS 已实测）

```bash
cd app
npm run tauri build     # 自动先跑 build:bridge（含于 npm run build）
```

产物：`src-tauri/target/release/bundle/macos/MFP.app`（+ dmg）。

已验证（macOS 实测）：
1. `Contents/Resources/dist-bridge/bridge-server.cjs` 存在（资源打包成功）；
2. 启动 `.app` → UI 挂载触发 `listWorkPackages` → **node 桥接服务自动拉起**
   （ps 可见 `bridge-server.cjs --root <MFP 根>`，无需任何环境变量）；
3. 退出 App 后子进程一并退出。

Windows 打包：需在 Windows 机器执行 `npm run tauri build`（NSIS/MSI 安装包），
资源落安装目录，resource_dir 候选同样命中——属真机验证项。
