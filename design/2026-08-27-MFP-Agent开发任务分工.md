# MFP MVP Agent 开发任务分工

> **父任务**：[GitHub Issue #1](https://github.com/jiahao89/MageneFirmwarePlayground/issues/1)
> **目标**：让 Claude Code 与 Antigravity 在同一项目上分工开发，避免重复修改和上下文丢失。

## 分工

| 子任务 | Agent | 主要产出 | 前置条件 |
|---|---|---|---|
| 项目骨架、本地桥接层与安全边界 | Claude Code | Tauri 壳、桥接接口、路径/进程安全约束 | 无 |
| 工作包、需求状态机与持久化 | Claude Code | 文件结构、状态迁移、读写服务 | 项目骨架 |
| Claude Code CLI 适配与终端启动 | Claude Code | 识别、启动、恢复、错误映射 | 工作包接口 |
| 原始需求输入与识别结果页 | Antigravity | React 页面、表单、识别结果展示 | 前端接口/mock |
| 需求池、澄清和 PRD 评审页 | Antigravity | 列表、状态、问答、Markdown 预览 | 前端接口/mock |
| 联调、跨平台测试与打包 | Claude Code | macOS/Windows 验证、最终 PR | 前端与桥接完成 |

## GitHub 任务约定

- Issue 标题使用 `[Claude Code]` 或 `[Antigravity]` 前缀，并保留 `ready-for-agent` 标签。
- 每个 Issue 必须写明：范围、非范围、依赖、允许修改目录、验收标准、测试命令和交付方式。
- 一个 Issue 对应一个分支和一个 PR。Issue 未关闭前，不把“看起来能运行”当作完成。
- Claude Code 子任务可以读取并更新工作包；Antigravity 子任务默认只读取工作包和 mock，不修改知识库、benchmark 或 Agent 编排。

## 你在本机的操作

### Claude Code

在 MFP 项目根目录启动 Claude Code，并把对应 `[Claude Code]` Issue 链接交给它：

```text
请先读取 AGENTS.md、CLAUDE.md 和 GitHub Issue <issue-url>。
你是本 Issue 指定的 Claude Code Agent，只执行该 Issue，不直接修改 main。
完成后运行验收命令、提交分支并创建 PR；如果遇到产品决策缺口，停下来向 PM 提问。
```

Claude Code 先完成桥接接口和 mock 契约，再承担最终联调。

### Antigravity

打开 Antigravity 的独立项目目录/ worktree，把对应 `[Antigravity]` Issue 链接和以下指令交给它：

```text
请先读取 AGENTS.md 和 GitHub Issue <issue-url>。
你是本 Issue 指定的 Antigravity 前端 Agent，只负责 React/Tauri UI，使用约定的桥接接口和 mock 数据。
不要修改 AGENTS.md、CLAUDE.md、knowledge-base、benchmark 或桥接安全边界。
完成后运行前端测试/构建，提交分支并创建 PR，报告截图、测试结果和未决问题。
```

如果 Antigravity 不能直接读取 GitHub Issue，就复制 Issue 正文，或将 Issue 正文保存为本地任务文件后交给它；任务契约不依赖某个 Agent 的 GitHub 插件。

## 分支与交付顺序

```text
main
├── agent/claude-mvp-bridge
└── agent/antigravity-mvp-ui
```

1. Claude Code 先定义桥接接口、工作包结构和 mock 数据。
2. Antigravity 基于接口开发前端，不等待真实 CLI 才开始。
3. 两边分别提交 PR；Claude Code 负责检查冲突、接入真实桥接、运行跨平台验收。
4. PM 检查 PRD/界面和验收结果后，再合并到 `main`。

## 禁止事项

- 不让两个 Agent 同时在同一个目录和分支中工作。
- 不让 Antigravity 自己决定新增运行时、API key 存储或后台自动运行。
- 不让 Claude Code 在没有 PM 确认时修改 benchmark、产品知识库或范围外功能。
- 不因为 Issue 已关闭就跳过真实 macOS/Windows 验收。
