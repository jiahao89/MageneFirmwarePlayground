# MFP MVP 实施方案

> **状态**：当前有效方案
> **对应 PRD**：`design/2026-08-27-MFP-本地产品经理Agent-简版PRD.md`
> **范围**：手动输入 + Web 识别 + Claude Code 单运行时
> **最后更新**：2026-08-27

## 1. MVP 产品形态

MFP MVP 采用本地桌面应用形态，内部包含 Web UI 和本地桥接层。推荐技术路线是 Tauri + React：

```text
PM
 ↓
MFP Web UI
 ├─ 原始需求输入、识别结果、需求池、问题、PRD、状态
 └─ 本地桥接层
     ├─ 读写 MFP 工作区
     ├─ 调用 Claude Code -p 做识别
     ├─ 设置 cwd 并启动/恢复 Claude Code
     ├─ 监听工作包变化
     └─ 打开文件夹和外部终端
          ↓
     Claude Code CLI
```

本期不做浏览器直接启动终端。普通浏览器没有权限可靠地打开指定目录和任意本地进程；如果未来提供浏览器版，必须另装本地 Helper/Bridge。MVP 直接用桌面壳解决这个问题。

## 2. 核心原则

1. **本地优先**：需求原文、任务卡、问题、答案、日志和 PRD 默认只存本机。
2. **Claude Code 作为唯一运行时**：MVP 不做 Codex、Trae 或其他 Agent 适配。
3. **Web 管工作流，Claude Code 做执行**：Web 不模拟 Agent 聊天；Claude Code 在外部终端工作，结果写回工作包。
4. **任务卡不是一次性 Prompt**：任务卡是随着阶段更新的工作合同，包含目标、输入、边界、可读文件、输出位置和暂停条件。
5. **PM 保留门禁**：Agent 可以识别、提问和生成草稿，但不能自行登记、完成或修改 benchmark。
6. **不保存 API Key**：Claude Code 的登录和 API 配置由 PM 自己维护，MFP 只检查 CLI 是否可用。

## 3. 端到端流程

```text
1. PM 在 Web 粘贴/手动输入原始需求
2. MFP 先保存 source.md，生成 RAW 编号
3. 本地桥接层执行 claude -p，返回结构化识别结果
4. PM 查看分类、功能需求改写、缺口和依据
5. PM 点击“登记为正式需求”
6. MFP 创建 REQ 工作包和 agent-task.md
7. MFP 检查 Claude CLI、规则文件、知识库、目录权限
8. MFP 以 MFP 根目录为 cwd，打开外部终端并启动 Claude Code
9. Claude Code 读取 AGENTS.md、任务卡和 benchmark，执行当前阶段
10. 如需澄清，Claude Code 写 questions.json 后暂停
11. PM 在 Web 回答，MFP 更新任务卡并恢复会话
12. Claude Code 写 PRD 到 output/{需求名}/02-PRD.md
13. PM 在 Web 审阅、提交修改或确认完成
```

## 4. 为什么识别也调用 Claude Code

用户看到的是 Web 端“开始识别”，但浏览器本身不直接调用模型。MFP 本地桥接层调用 Claude Code 的非交互模式：

```text
claude -p <识别指令> --output-format json --json-schema <schema>
```

这样可以复用同一台电脑上的 Claude Code 登录态、项目规则和知识库，同时不需要 MFP 自己维护 API Key。识别结果写入：

```text
intake/RAW-YYYYMMDD-NNN/classification.json
```

识别失败时，原始文本仍然保留；Web 展示失败原因和“重试”，不得创建空的正式需求。

## 5. Claude Code 自动启动方案

### 5.1 用户体验

PM 在 Web 点击“在 Claude Code 中开始”后：

1. 页面显示启动前检查；
2. 检查通过后，MFP 自动打开 Terminal/Windows Terminal；
3. 终端启动在 MFP 项目根目录；
4. Claude Code 自动进入新会话，并收到当前任务卡路径和本轮目标；
5. Web 保持在需求详情页，等待工作包状态变化。

因此答案是：**需要打开指定目录，也需要自动开启会话。** 这是 MVP 对 PM 最有价值的“去命令行化”能力。

### 5.2 启动契约

启动器使用进程 API，不拼接不安全的 shell 字符串：

```text
executable: claude
cwd: MFP 项目根目录
args:
  --name "MFP · REQ-YYYYMMDD-NNN"
  <读取 AGENTS.md、读取 agent-task.md 并执行本轮工作的启动指令>
```

启动指令最少包含：

```text
请先读取 <MFP_ROOT>/AGENTS.md。
然后读取当前任务卡 <MFP_ROOT>/requests/<REQ_ID>/agent-task.md。
按任务卡执行当前阶段；如果信息不足，把问题写入
<MFP_ROOT>/requests/<REQ_ID>/questions.json 并暂停，不能只在聊天窗口提问。
所有产物写入任务卡指定位置，并在 run-log.ndjson 记录本轮结果。
```

首次启动创建新的 session id 并写入 `session.json`。PM 点击“继续”或“要求修改”时，优先使用：

```text
claude --resume <session-id> <读取更新后的任务卡并继续工作的指令>
```

如果会话不存在或恢复失败，则创建新会话；新会话读取完整工作包，不依赖旧聊天记录。

### 5.3 跨平台启动

| 平台 | 实现方式 |
|---|---|
| macOS | 默认打开 Terminal；设置中可选择 iTerm2。进程 `cwd` 指向 MFP 根目录 |
| Windows | 优先打开 Windows Terminal；不可用时回退 PowerShell |
| 共同 | 任务卡、规则文件和工作包使用绝对路径；不把 API Key 写入命令行或日志 |

## 6. 工作包协议

```text
MFP_ROOT/
├── AGENTS.md
├── .ai_global_profile.md
├── knowledge-base/
├── intake/
│   └── RAW-YYYYMMDD-NNN/
│       ├── source.md
│       └── classification.json
├── requests/
│   └── REQ-YYYYMMDD-NNN/
│       ├── request.json
│       ├── agent-task.md
│       ├── questions.json
│       ├── evidence.md
│       ├── revision.md
│       ├── session.json
│       ├── run-log.ndjson
│       └── artifacts/
└── output/
    └── {需求名}/
        └── 02-PRD.md
```

### 6.1 `agent-task.md` 必须包含

- 当前阶段和本轮目标；
- 原始需求与 PM 已确认的结构化描述；
- 已确认边界和待确认项；
- 允许读取的规则、benchmark 和技能路径；
- 预期产物和写回路径；
- 事实、判断、待确认的区分要求；
- 必须暂停的条件；
- 禁止修改 benchmark、自动完成需求等约束。

### 6.2 Web 如何知道 Agent 做到了什么

MVP 不读取 Claude Code 的内部对话作为状态真源，而是读取工作包：

- `questions.json`：Agent 要 PM 回答的问题；
- `run-log.ndjson`：启动、暂停、写回和失败记录；
- `request.json`：需求状态、阶段和更新时间；
- `artifacts/`：阶段产物；
- `output/{需求名}/02-PRD.md`：PRD 真源。

优先使用文件变更监听；无法使用时按 1–3 秒轮询需求工作包。

## 7. 分阶段实施

### P0：不做 UI，先验证接缝

1. 手动建立一个 `REQ` 工作包和 `agent-task.md`。
2. 验证 Claude Code 能从 MFP 根目录读取 `AGENTS.md`。
3. 验证 `claude -p` 能返回符合 JSON Schema 的识别结果。
4. 验证外部终端启动时 `cwd` 正确，Claude Code 自动进入新会话。
5. 验证 Claude Code 写 `questions.json` 后，PM 填答并用 `--resume` 继续。
6. 验证 PRD 能写入 `output/{需求名}/02-PRD.md`。

### P1：可日常使用的 MVP

1. 初始化本地 MFP 工作区并检查规则/知识库文件。
2. 完成原始需求输入、保存和识别结果页。
3. 完成正式需求池、需求详情、状态和工作包创建。
4. 完成 Claude Code 检查、Terminal/Windows Terminal 启动和 session 管理。
5. 完成问题/答案、继续、PRD 预览、修改意见和完成确认。
6. 完成错误提示、工作包恢复、日志诊断和安装包。
7. 在一台 macOS 和一台 Windows 电脑上各完成一次真实闭环。

### 后续版本

- Codex、Trae 和其他 Agent 适配；
- Teambition skill 导入；
- 飞书发布；
- 附件/图片/OCR；
- 团队共享、云同步和效率看板。

## 8. 主要风险与控制

| 风险 | 控制方式 |
|---|---|
| 浏览器无法启动 CLI | MVP 使用 Tauri；浏览器版必须安装 Helper |
| Claude Code 未安装或未登录 | 启动前检查，保留原文并提供安装/重试提示 |
| Agent 只在聊天里提问 | 任务卡强制写 `questions.json`，Web 只认工作包 |
| CLI 会话关闭 | 所有上下文写入工作包；可恢复旧 session 或创建新 session |
| 规则/知识库路径错误 | 启动前检查 `AGENTS.md`、benchmark 和工作包可读性 |
| PM 误以为 Web 内嵌了 Agent | UI 明确区分“Web 操作台”和“Claude Code 外部会话” |
| 命令注入或路径错误 | 使用进程 API 参数数组，不拼接 shell；路径白名单限定在 MFP 工作区 |

## 9. 完成定义

一个不熟悉 Git 的 PM 能在自己的 Mac 或 Windows 电脑上：手动粘贴需求 → 在 Web 查看 Claude Code 识别结果 → 确认登记 → 点击按钮后自动打开 MFP 指定目录并启动 Claude Code 会话 → 在 Web 回答澄清问题 → 查看 PRD → 要求修改或确认完成。关闭 Web 或终端后，需求仍可根据本地工作包恢复。
